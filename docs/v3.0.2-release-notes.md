# amq-squad v3.0.2

amq-squad 3.0.2 is a fix release on the 3.0 line. The module path is
unchanged:

```sh
go install github.com/omriariav/amq-squad/v3/cmd/amq-squad@v3.0.2
```

3.0.2 is the second fix release. It is built from the second dogfood day, on
2026-10-30 (session v31), on the installed 3.0.1 binary, and from the 3.0.1
release itself. The squad's two seat fixes, t12 from the dev seat and t19 from
the reviewer seat, could not land through the merge train because of three
harness defects: a relaunched seat was reset to its first day's base, so both
fixes sat on stale bases; the commit step pushed a second task's commit onto a
branch whose PR was bound to the first task, and only then refused the
binding; and every task of a seat shared one seat branch. 3.0.2 fixes the
harness and lands the two seat fixes, cherry-picked onto the tip with the
reviewer's rulings and the seats' own commits kept. The release also takes
three follow-ups from publishing 3.0.1. The items below were built outside the
squad, by agents under the owner's decision of 2026-10-31, each with the
reviewer's read, one to three Codex rounds and the lead's gate. Upgrading from
v2: see [MIGRATION.md](../MIGRATION.md). The earlier notes are
[docs/v3.0.1-release-notes.md](v3.0.1-release-notes.md) and
[docs/v3.0.0-release-notes.md](v3.0.0-release-notes.md).

## A seat's base is the base branch's tip at every launch (#820, t22)

- At every launch, the roster launch included, a seat's worktree and its
  resting branch `seat/<handle>` start at the base branch's tip. The tip is
  fetched from the grant's push URL into a shadow git directory, so the shared
  repository's config, remotes and URL rewrites are never read. Without a push
  URL in the grant, the local base branch is the tip.
- An HTTPS push URL fetches with the push's authentication: the launch's
  pinned gh, re-hashed, is the only credential helper. A missing pin refuses
  with `tool_unpinned` and a hash mismatch with `tool_pin_mismatch`, before any
  network call. SSH and local URLs are unchanged.
- An existing worktree moves to the tip by a two-tree read-tree from its HEAD,
  never a reset, and every write of the resting branch passes its expected old
  value. Nothing a seat holds is lost. Six refusals name what stopped the
  launch:
  - `seat_branch_unmerged`: the remote seat branch is ahead of the tip and
    unmerged. The harness never force-pushes.
  - `seat_branch_unpushed`: the local seat branch holds commits the tip does
    not.
  - `seat_head_detached_unmerged`: the worktree's HEAD is at a commit the tip
    does not hold.
  - `seat_head_unreadable`: the worktree's HEAD names no commit.
  - `seat_gitdir_foreign`: the worktree's `.git` is a symlink, or does not
    lead to its own git directory under the project repository's worktrees.
  - `base_tip_moved`: the fetched tip is not the object id ls-remote reported.
- A local change the move would overwrite refuses the launch and stays in the
  worktree. A plain clone used as a seat worktree moves like a linked one.
- The launch record carries the base, as `base`. The seat file cannot set it.

## The binding check before the commit and the push; one branch per task (#821, t24 and t23)

- The commit step checks the PR binding before any commit or push. It lists
  every open PR on the task's branch. A PR bound to another task or to none,
  or from another repository or onto another base, refuses
  `pr_bound_elsewhere` naming it. A gh failure, or a full page of 100 PRs,
  defers as `pr_pending`. On day 2 the step pushed t20's commit onto PR #815,
  bound to t12, and refused only afterwards; that order is gone.
- A step refused or deferred by the path checks or the binding check leaves the
  commit ledger byte-for-byte unchanged. A quarantine records its evidence, and
  an owner's verified clear is lifted, only after the binding check passes.
- A retry of a recorded commit is checked again against the grant in force
  now, with its diff digest recomputed. A digest that does not match refuses
  `recorded_diff_mismatch` to the owner.
- Each task gets its own branch, `seat/<handle>-<task id>`, cut from the remote
  base tip fetched at the grant. The name is a label only. The ledger's lease
  record is the only source of which task a branch carries. The step pushes the
  task's branch and opens and binds its own draft PR. A later attempt appends to
  the same branch and binds the same PR again at the new head.
- If the grant cannot fetch the tip or move the worktree onto the task's
  branch, the seat is not rung. The task is blocked for the lead as
  `task_branch_unprepared`, with the error as the detail, and the lease is
  released in the same store transaction.
- After an OK step, and at every lease boundary, the worktree returns to the
  resting branch at the launch record's base. A launch record from before 3.0.2
  keeps the ledger's resting commit, and the step notes `launch_base_missing`.

## A task's pool is fixed once its first attempt is granted (#817, t12)

- The dev seat's commit c338d3fe is kept with its authorship, cherry-picked
  onto the tip.
- A task's pool can be re-pinned until its first attempt is granted. After
  that, `task set --pool` refuses with `repin_after_attempt`, a code callers
  match with `errors.Is`. A task back in pending after an unclaimed expiry
  keeps its attempt count and is refused too.
- The refusal names the reset path: release the task's lease if it has one,
  block it if it is not blocked, then use `task reset --pool`.
- The router takes a re-pin made before the grant on its next route, and a
  restarted router reads it from the decision log.

## The team-mode lead takes the squad's identity (#818, t19)

- The reviewer seat's commit e9e6c53b is kept with its authorship,
  cherry-picked onto the tip with 3.0.1's roster launch kept whole.
- `lead --team --scheduler-seats FILE` gives the pi lead the squad's AMQ
  identity from the seats file: AM_ME the lead handle, AM_ROOT, AM_BASE_ROOT
  and AM_SESSION. In 3.0.1 the lead ran in solo mode, and its task tools read
  an empty store while the scheduler leased from the squad's.
- An identity already in the environment, AM_ME and AM_ROOT, must agree with
  the seats file's root, base root and session. A disagreement refuses at
  start, before the scheduler starts, naming both values.
- AMQ_SQUAD_PROJECT is the seats file's project root, not the directory the
  lead started in.
- The lead derives its root with exactly the scheduler's steps, so the pi lead
  and the scheduler pin one store. The scheduler the lead starts takes the
  lead's handle.

## The release body from a file, and the follow-ups from 3.0.1 (#819)

- `release prepare` and `release publish` require `--notes-file PATH`, whose
  content is the GitHub release body. `--notes` stays the gate note. On
  2026-10-30 the gate note became v3.0.1's public body and was fixed by hand.
- The body's sha256 is in the signed note of the release spec, so the owner's
  gate question shows the digest being approved. Only prepare writes it:
  a `--notes` that already carries one refuses `note_carries_digest`. Publish
  refuses `release_body_digest_missing`, `release_body_digest_ambiguous` and
  `release_body_mismatch` before anything runs.
- The draft's body on GitHub is compared at every read-back: at recovery,
  after creation or adoption, and before publication. A draft edited on GitHub
  refuses `release_draft_body_changed`. A published release whose body differs
  is never deleted.
- `--commit` is resolved before any gate is raised. It must exist locally
  (`commit_unknown`), exist on the remote (`commit_unknown_remote`) and be
  contained in `--branch`, default main (`commit_not_on_branch`).
- gh's HTTP status is read only from gh's own trailing `(HTTP nnn)` suffix. A
  failure without it stays an error.
- The pi lead's `amq_task_widen` refusal names the lead's way out for a seat's
  own block with a widen request: `amq-squad task reset <id> --pool
  RUNTIME:MODEL:EFFORT`.
- The release check gains an opt-in marketplace row: with
  `MARKETPLACE_REF=origin/main`, both plugin manifests at that ref must carry
  the version. CI's check on a version-bump PR into v3 runs without it.
- The orchestrator skill's release example carries `--notes-file`.

## Owner steps before the first 3.0.2 run

1. Close #815 and #816 as superseded by #817 and #818, which carry the seats'
   commits c338d3fe and e9e6c53b. Then delete `seat/dev` and `seat/reviewer`
   on origin and locally. The local copies carry the same commits.
2. Install by temp and rename: build from the v3.0.2 tag with
   `scripts/build-pi-runtime.sh` into a temporary directory, then rename the
   binary over `~/go/bin/amq-squad`, so macOS sees a fresh inode. Never build
   it from the working tree.
3. Clear the scribe seat with the signed `amq-squad seat clear --seat scribe`
   from the owner's own terminal, citing #809.
4. Start the lead in tmux with
   `amq-squad lead --team --scheduler-seats FILE --trust`. Since #818 the lead
   takes its identity from the seats file, so nothing needs to be exported.
5. If a step above is skipped, the first launch refuses by name:
   - `seat_branch_unmerged`: the remote seat branch is ahead. Delete it or
     merge it.
   - `seat_branch_unpushed`: the local seat branch is ahead. Delete it or push
     it.
   - `task_branch_unprepared`: the grant could not fetch the tip or move the
     worktree. The task is blocked for the lead. Read the detail, fix the
     cause and reset the task.

## Recorded limits

- A pane that outlives its process leaves the roster unreplaceable until AMQ
  can join a fresh participant into a present binding (ask 20, filed upstream
  by the owner).
- The create-to-bind window: if the process dies after GitHub creates the
  draft PR and before the binding is stored, the next attempt refuses
  `pr_bound_elsewhere`. The 3.1 fix treats an open PR whose branch equals the
  task's own branch name, compared whole, and whose head equals the ledger's
  recorded pushed commit as this task's PR, and binds it again.
- The release body's digest lives in the spec's one note field. A typed digest
  field on the spec comes in 3.1, when the spec's shape changes anyway.
- `release publish` must still repeat prepare's `--notes` and `--notes-file`.
  When the notes file changed, the spec-change refusal fires before
  `release_body_mismatch` and does not name the field.
- `remote attach` does not start the amq-remote endpoint and does not notice it
  gone. An attach moved between sessions loses the owner's answers until the
  endpoint is restarted by hand.
- The plugin marketplace reads the repository's main branch. The 3.0.2 plugin
  is installable from it after v3 is merged to main.
- A task that depends on another, still unmerged task starts from the base tip
  without that task's commit.
