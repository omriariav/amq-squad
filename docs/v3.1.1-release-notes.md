# amq-squad v3.1.1

These are the notes for the 3.1.1 release, built from the tip of v3. 3.1.1
makes the squad readable. The lead's screen says in words what each seat is
doing. Each action is its own command. A gate question on the phone is three
plain lines, answered with a bare yes or no. The merge train waits for real
merges and proves what it lands. The module path is unchanged.

```sh
go install github.com/omriariav/amq-squad/v3/cmd/amq-squad@v3.1.1
```

A `go install` build carries no embedded pi runtime. The binary the squad runs
is built from the tag by `scripts/build-pi-runtime.sh`, as the owner steps
below show. The earlier notes are
[docs/v3.1.0-release-notes.md](v3.1.0-release-notes.md) and the notes it
links.

## What 3.1.1 is

3.1.1 answers what the owner said after trying 3.1.0 on 2026-11-01. On the
lead's screen:

> "the /squad thing is not clear enough imho"

> "i want seamless like claude agents teams so whoever leading can see easily"

On the gate questions, after answering the rc.1 gates on the phone:

> "simple language not these hash and unclear language"

> "Why adding a code? It's Buzz and it's authenticated and safe."

So 3.1.1 has one rule for anything the owner or the lead reads. A plain line
says what happened and what to do. A line of hyphens follows. The codes and
ids sit below it, for the record. These notes follow the same rule: each
section ends with a line, and its records sit below it.

The rest of 3.1.1 is fixes from running the squad on 3.1.0. Most of them are
the merge train's. The work was built by the squad's own reviewer seat and by
agents in scratch worktrees. Codex and the plan reviewer read the work, and
their findings are in each execution note.

## The lead's screen and its commands

- **One command per action.** Before the team starts, `/plan` shows the
  proposed team and `/confirm` starts it. With a team, the commands are
  `/add`, `/reset`, `/dismiss`, `/answer` and `/widen`. `/team` shows the
  screen in both phases, and `/team hide` hides it.
- **The screen is on by default.** Its last line lists the commands you can
  use now. That line changes when the phase changes.
- **The model cannot press a command.** pi runs a command in the extension and
  never sends its text to the model. No command is also a tool. The lead's
  tools are unchanged.
- **Each seat line says what the seat is doing.** For example "working on t2:
  Write the notes", "idle", "starting", "waiting: on your answer to its gate"
  or "stopped". The launch time moves to the end of the line.
- **Each task line says why it waits, or what stopped it and what to do.** For
  example: "t1 blocked: the commit step refused it, it changed files outside
  its task; accept them with /widen or send it back with /reset".
- **Warnings and stops are sentences too.** A seat warning says what it means
  and what to do. A stopped seat or a stopped train says what happened and
  what to do. A failed launch says which step failed.
- **`/confirm` is a dialog with nothing to type.** It quotes the goal, the
  session, the lead and each seat. Yes starts exactly those seats. The
  yes holds for 30 minutes. A plan proposed while the dialog is open is not
  the one confirmed.
  No, or a cancel, sends nothing.
- **`/widen` is a dialog too.** It shows the files the seat asks to touch and
  the seat's reason, both from the task's record. Yes adds exactly those files
  to the task. No changes nothing.
- **Every name Go can record has words.** A test reads Go's sources and fails
  on any wait, block, launch failure, train rule or decision without words.
  Each scheduler decision is either a stop the lead sees or a routine record.
  A decision no table knows still shows, never hidden.
- **A stop clears when its fix arrives.** "seat dev's process is gone" clears
  when dev comes up again, or when the roster launches. Some stops have no
  such record; see the known limits.
- **The permission warning says only what its record holds.** It reads "seat
  scribe asked for a permission 3m0s ago this turn; if it is not moving, check
  its pane". Its record cannot tell a stuck seat from an approved prompt.
- **`/squad` is the old name.** It lists the commands you can use now and
  changes nothing. It goes in 3.2.

## Gate questions in plain words, answered yes or no

- **Every gate question is three plain lines.** What is asked, why now, and
  what yes and no do. The ids sit below a line, for the verifier.
- **The second line states only a recorded fact.** For a release: "The
  prepare found its commit on v3." For a merge: the train's own refusal, in
  words. With no fact on record, it names who asked.
- **The answer is a bare yes or no, replied in the question's thread.** Case
  and a trailing full stop do not matter. "approve" and "deny" work too. The
  thread and the owner's signature bind the answer. No code is typed.
- **A yes outside any thread is asked again.** The re-ask, "Reply yes or no to
  this message.", goes into the one open gate's thread. With several gates
  open, nothing is re-asked.
- **A team is confirmed the same way.** Reply yes to the lead's Buzz post of
  the plan. The lead checks that the post is its own recorded plan, word for
  word.
- **The lead's screen and `/answer` show the same plain lines.**
- **The old typed line still verifies.** Nothing asks for it any more.

## The merge train waits, records and proves

- **A task waits for its dependency's PR to merge.** Before, a dependency
  released the tasks waiting on it when it completed. Now, if it has a PR, it
  releases them only once the merge is recorded. The waiting task reads
  "waiting for t27's PR #812 to merge".
- **The merge record names the head that merged.** If the task was later
  bound to a new head, the old merge no longer releases anything.
- **The train reconciles what it finds.** A journaled merge that no longer
  matches its task is skipped and audited, and the run goes on. A PR GitHub
  already reports merged, at the bound head, is recorded with no merge call.
  At another head it is audited and not recorded.
- **A PR merged by hand: run the merge train on the PR.** That records the
  merge and releases the tasks waiting on it. It is also the way to release
  tasks whose PR merged before 3.1.1.
- **The train honours GitHub's rule that a branch be up to date.** It asks
  GitHub's compare whether a PR is behind its base. It asks again before each
  landing, against the base as the train has moved it. A behind PR is brought
  up to date, waits for its checks, then merges.
- **An updated PR is re-bound only if the seat's change is unchanged.** The
  train compares the seat's patch before and after GitHub's update. If it
  moved, the PR is refused: "#N was not merged: its change moved during the
  update". If GitHub's diff comes back incomplete, the update cannot be
  proved, and the PR is refused.
- **The dry run refuses what the real run cannot do.** It reads the same task
  binding as the real run. A behind PR it cannot update safely, such as one
  with a conflict, is refused in the plan.
- **The train's text is in words.** Its plans, refusals and stops open with a
  sentence. The rule and the full heads follow on later lines and in JSON.
- **The cost.** Under the up-to-date rule the train lands one PR per CI cycle.
  Every PR after the first waits for a fresh run of its checks.

## Refusals that are not failures, and the roster as it runs

- **A policy refusal is not a failed attempt.** The size cap, files outside
  the task, a protected path and a growth gate no longer count against the
  work. After the lead's reset, the task retries on the same tier, not one
  up. One table classifies every reason the commit step can give.
- **A seat's typed widen request is not a failure either.** A free-text block
  from a seat still counts, on purpose; see the known limits.
- **An expired lease counts, but does not move the task up a tier.** The
  retry stays on the same pool, and the lead's pin is kept. It still counts
  toward the task's attempts. A task that expires every time ends blocked for
  the lead, as usual.
- **No seat for a pool is a named wait.** The task line reads "waits: no seat
  serves claude:opus:high". Before, the scheduler logged a line every two
  seconds; one task's loop wrote over 8,000 lines. A failed on-demand seat
  request now backs off, from 2 seconds up to 5 minutes.
- **status lists the running roster.** Seats from earlier sessions under the
  same root move to a separate list. The screen shows only the roster.
- **The lead's tool list is one list.** The extension's list equals Go's.
  Claim, done and block are seat tools, not the lead's.
- **The local release check runs every validator CI runs.** It found one
  disagreement: one script accepted non-ASCII digits in a version. It now
  takes ASCII only.
- **The train's tag and release check reads every session.** A release cut in
  its own session no longer raises an "ungated tag" alert. An alert clears
  only on an owner-signed gate naming that tag and its commit. A gate store
  it cannot read is an alert of its own.

## Widening a task: the typed request

- **A seat asks to widen in a typed record.** Its block names the exact files
  it needs and its reason. The lead's `/widen` dialog shows both.
- **The request survives the owner's growth gate.** While the gate waits, the
  files are kept. On the owner's yes, the task goes back to the queue.
- **Paths are exact files.** Directories, parent steps, absolute paths and
  backslashes are refused. Every load of the task store checks them.
- **A link is judged by its target.** A link into a protected path meets the
  protected-path gate. A link outside the repository, dangling or in a loop is
  refused. The gate question names the real file; the link sits below the
  line.
- **The commit step and the verifier read links from git's own objects.** They
  never follow the filesystem. A file that turns into a link is caught too.
- **An approval is for a file, not a spelling.** A second link to the same
  approved file reuses the approval.
- **The size check measures the stopped attempt, never the live tree.** The
  scheduler archives the stopped attempt when the seat blocks. If that archive
  is not taken yet, `/widen` takes it on the spot. The first archive written
  is kept, and a retried attempt archives its own.

- **The tests behind three fixes check more.** They cover the retried
  attempt's archive, the train's incomplete diff and the expired lease. Only
  tests and notes changed.

## Owner steps for 3.1.1

Install by temporary name and rename, from the tag, never from the working
tree (R54). If the installed binary is 3.1.0, the 3.1.1 release's own gate
questions still read the old way.

1. After the gates are answered and the v3.1.1 tag is published, build the
   tag in a scratch worktree. `scripts/build-pi-runtime.sh all` fetches the
   pi runtime, then builds:

   ```sh
   git worktree add ~/scratch-v311 v3.1.1 && cd ~/scratch-v311 && scripts/build-pi-runtime.sh all
   ```

   The binary is `build/pi/amq-squad`.
2. From the repository, run `up` from the tag build. It installs itself over
   the `amq-squad` on PATH, then starts the squad:

   ```sh
   cd ~/code/amq-squad
   ~/scratch-v311/build/pi/amq-squad up --binary ~/scratch-v311/build/pi/amq-squad
   ```

   If a step refuses, `up` names it and nothing after it runs. The 3.1.0

## Known limits

1. A Codex seat keeps its lease only by renewing it itself. A seat that
   forgets is closed when its lease runs out.
2. A seat can claim any pending task by its id, whatever pool the task is
   routed to.
3. A seat whose attempt on a task lapsed is not handed that task again by the
   scheduler.
4. The permission warning says only that a request was made this turn. It
   cannot tell a stuck seat from a working one.
5. Twelve kinds of stop have no record that clears them. Each stays on the
   screen until it leaves the last 30 decisions. A morning error on a quiet
   squad can stay all day.
6. The `/confirm` dialog's file count is a size hint, not an exact count.
   There is no cost line.
7. A waiting task names AMQ's launch failure only while that failure is in
   the last 30 decisions. After that it reads "waiting", its code below the
   line. A blocked task keeps its reason.
8. The merge train's plan text still shows some commit ids and rule names
   above its line.
9. A passing error reading GitHub while reconciling stops the whole run.
   Running it again fixes it.
10. A PR that GitHub reports merged at another head is audited again on every
    run.
11. With the size cap set very high, the size-driven growth gate stops firing.
    The protected-path gate is unchanged.
12. A dry run still writes its protection, batch and plan entries to the
    audit log, marked as a dry run.
13. An owner gate can lift the train's up-to-date refusal. GitHub then
    refuses the merge anyway.
14. A seat's free-text block still counts as a failed attempt. This is on
    purpose: a seat cannot dodge its attempt limit by blocking. A typed widen
    request does not count.
15. The first-message time from the day-4 launch run is still not recorded.
    So the first message still has no ceiling.
16. The widen's size check measures the attempt as archived at the block. The
    commit step measures again when it commits.
17. A gate record lists at most 64 resolved links. The rest read "and N more",
    below the line.
18. An approval binds a file, not its spelling. Another link to an approved
    file needs no new approval.
19. Before the yes, the solo lead still holds the owner's shell. A model
    typing into its own pane is the one path left. The named close is a 3.2
    candidate: a sandbox for the solo lead's shell.
20. doctor's tag and release check removes a covered alert without an audit
    entry, since doctor keeps no audit log.
21. No test signs a gate end to end through the train's verifier. The check of
    each session's namespace is read from the code.
22. A branch or tag name with a slash would show above a gate question's line.
