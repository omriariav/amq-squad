## The shape

`seat commit` (internal/seatcommit, `Run`), in this order (rule 7, as the code runs it): the exit check (the global-config `PreflightDiff`, the Claude config dir, the store's quarantine), the snapshot, the diff checks on the snapshot (against the declared set, the protected paths, the size cap) and the push-target checks, then `verify` (verifier.go): the class's verifier on the snapshot tree, the exit check again (rule 10), the sealed verdict; only a pass reaches `commitAndPush` (commit, push, PR).

- The command (rule 1, 9): `planVerifier` reads `verifiers.<class>` from the resolved grant (the owner grant as squad.yaml narrows it; squad.yaml adds gate classes, never removes one), split on blanks, no shell. argv[0] is an absolute clean path to a regular file, or a registry pin name resolved through `registry.OpenPinned` (re-hashed now; run by `VerifiedTool.Command`). A name with no pin (`go test ./...` with no `go` pin) and a relative path are `grants_invalid`; a pin whose file no longer hashes to its digest is the pin's own code (`tool_pin_mismatch`) for the owner. Nothing is looked up on PATH; nothing is read from the seat's tree.
- The shadow worktree (rule 1): a fresh `amq-squad-verifier-*` directory under the system temp dir holds `work/` (the checkout), `home/`, `tmp/`, `gocache/`, `gotmp/`, `gopath/`. `checkoutTree` writes the snapshot tree's files from the object store through the harness shadow (`ls-tree -r -z`, one `cat-file --batch`): no filter, attribute or hook applies, so the files are the snapshot's bytes; a path with an empty, `.`, `..` or `.git` component, or under a parent that is not a real directory, refuses (deferral). The directory is removed after the run (read-only module-cache dirs made writable first).
- The environment (rule 8), built from nothing, no variable carried from the harness: `PATH` = the core tools directory (`ToolsDir`, `<root>/extensions/amq-squad/tools`) only; `HOME`, `TMPDIR`/`TMP`/`TEMP` under the private dir; `GOENV=off`, `GOCACHE`, `GOTMPDIR`, `GOPATH` under it (fresh per run, never the harness's); `GOWORK=off`, `GOTOOLCHAIN=local`, empty `GOFLAGS`; `LC_ALL=C`; `GIT_TERMINAL_PROMPT=0`, `GIT_CEILING_DIRECTORIES` at the private dir, and the hardened git set (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_ATTR_NOSYSTEM=1`). No credential, no token path, no gh helper, no `AMQ_SQUAD_BIN`, `AM_*` or `CLAUDE_CONFIG_DIR`.
- The bounds (rules 1, 12): `verifier_timeout` (default 10m, at most 24h), `verifier_output_limit` (bytes, default 1 MiB, at least 1024), `verifier_parallelism` (default 2), new owner-grant keys. The verifier leads its own process group (`Setpgid`); at either bound the group is killed with SIGKILL, and once more after Wait; `WaitDelay` (2 s) closes the output pipe an escaped descendant holds. Combined stdout and stderr go to one bounded buffer: past the limit the rest is dropped, the group killed, and the marker `[amq-squad: verifier output truncated at N bytes]` appended. Slots are lock files `<root>/extensions/amq-squad/verifiers/slot-<i>.lock` (`flock.TryExclusive`); while every slot is held the step writes `verifiers/waiting/<seat>.json`, which `status` shows as attention `verifier_waiting` (working), and waits (polling, bounded at twice the timeout plus a minute, then a deferral).
- The verdict (rules 1, 2, 6, 11): exit 0 is pass, anything else fail; a bound is fail with `verifier_timeout` or `verifier_output_exceeded` (`verifier_start_failed` when the command cannot start). The output passes `redact.Text` (binary output too) and goes whole into the seat's evidence ledger (`ledger/<seat>.jsonl`, event `harness_verifier`, payload: task, attempt, class, command digest, tree, exit code, reason, duration, output) through `ledger.Append`, the hook ledger's one writer (moved from the ingest verb so both use it). Before the run the step records the snapshot tree on the lease (`task.Store.RecordSnapshot`); after it, `RecordVerdict` with the tree and `CommandDigest` (sha256 of the grant's command line). The store refuses a verdict whose tree is not the lease's snapshot, or with no snapshot (`verdict_tree_mismatch`), and never moves a snapshot under a recorded verdict; it seals the verdict with the session seed (`sealchain.Tag`, label `amq-squad verdict v1`, over task, attempt, holder, verifier, result, source, detail, tree, command digest, time). Completion (`complete`) verifies the seal and the tree: a verdict without them is dropped from the lease (never carried to the attempt) and the gate reads `verdict_missing`, naming why. A fail refuses the step with `verdict_failed`, routed to the lead, the detail the run's head line plus the output's tail, at most 4 KiB (`task.VerdictDetailCap`); the attempt ends `commit_refused` carrying the fail verdict, which routing counts as a failed attempt. A re-run of the step on the same tree and command (a deferred push or PR) reuses the attempt's verdict and does not run the verifier again.
- Harness only (rule 2): no task verb records a snapshot or a verdict; guard denies a seat's `amq-squad seat commit` and `amq-squad scheduler run` (any path, wrappers, `sh -c`) as `harness_only`; `seat commit` refuses when `AMQ_SQUAD_SEAT` is set.
- Dispatch refusal (rule 4): the router's start step computes the gate's classes with no command (`Grants.UnconfiguredGate`, beside the head checks) and `Route` blocks a task of one for the lead, `grants_invalid`, naming the class and `verifiers.<class>`. The store refuses `Grant` and `Claim` of such a task (`VerifierUnconfiguredError`, the same message), and a pull skips it; the scheduler turns that refusal (the grant changed after the start) into a lead block instead of a failed tick. So `verdict_missing` fires only on a change during a lease, at the commit step (gated, no command: refused before any push) or at `done`.
- The R12 probe (rule 3, with the lead's ruling on its reading): each `RunProbe` run gets `Tree`, the probe checkout's tree (hashed with no filter into a scratch object store of its own, the model's `.git` left out) after the model's processes are gone, and `Verdict`, the predicate as a verdict built like the commit step's: verifier `r12`, pass exactly when the predicate holds, the failed checks as detail, command digest over the predicate version and the prompt (`PredicateDigest`). doctor's probe runs outside any session: `ProbeRecord.Verdicts` are unsealed, their source says so, and doctor's check line says so. When the probe runs as a scheduled task (milestone B's probe role through the scheduler and the commit step) the harness records the run on that task's lease with `registry.RecordProbeVerdict`: the checkout tree as the snapshot, the predicate as the verdict of the task class's verifier, sealed by the store with the session seed through `RecordVerdict`; the task completes only on it.

## Judgment calls

- Rule 3's reading (stated to the lead, accepted): doctor's probe has no task or session, so its verdicts are built by the same constructor and recorded on the probe record unsealed, saying so (`ProbeRecord.Verdicts` through `Tally`, which doctor calls). The scheduled-probe recorder of the first commit (`RecordProbeVerdict`) had no production caller and is removed (the fix commit, P2-b). RunProbe's per-run tree and verdict wiring is an owner-session acceptance row with the pi seat.
- The probe tree's `.git` skip has no revert row: the reverted run still passed, because `update-index` itself refuses a `.git` path, so the skip is defense in depth. Five cases of the first revert run were harness errors (a revert that did not build) and were rewritten so the reverted code builds; the second run is the evidence.
- The verdict's seal is the store's: `sealchain.Tag` under the session seed (the key the commits ledger, the exits queue and the routing chain use), over the verdict inside the task file, checked at completion by the store itself; the verdict is not also appended to the seat's commits ledger (the task package cannot read it, and the completion gate is the store's). "Writes through the sealed ledger" is read as the same seal and seed.
- The tree digest is the snapshot's tree id (the object store's own digest of the tree, sha1 or sha256 by the repository's object format), recorded as is; "the sha256 of the tree" is read as the digest that names the tree.
- The verifier's argv is the grant's line split on blanks: no shell, no quoting. A pinned tool is run through `VerifiedTool.Command` (the hashed descriptor on Linux, the verified path elsewhere), not copied into the tools directory; PATH is that directory, which may hold nothing a verifier calls by name.
- The fix commit replaces this: GOPATH, GOCACHE and GOTMPDIR stay private per run; the module cache is the verifier's own under the session root (see the fix section). `GOWORK=off` and `GOTOOLCHAIN=local` stay, so the seat's tree cannot pick a workspace or a toolchain download.
- The fail verdict is the commit step's refusal (`RefuseCommit` with `verdict_failed`): the report stays, the seat stays reserved until the lead's reset, as for every refusal; the attempt is `commit_refused` with the fail verdict on it. A gated class with no command at the commit step refuses `verdict_missing` before any push.
- `verifier_parallelism` counts per session root (the slots live under it), and a step waits for a slot for at most twice the timeout plus a minute before deferring.
- The scheduler's start check blocks the task (`Route` with `grants_invalid`) rather than refusing to start the process: the other classes keep dispatching.
- The harness's verifier line in a seat's evidence ledger is skipped by status's activity read (it is not the seat's activity).
- `seat commit` refuses inside a seat by `AMQ_SQUAD_SEAT` (the release verb's test); the lead or the owner may still run it by hand.

## Behavior changes

- `seat commit` runs the class's configured verifier on the snapshot tree before it pushes; a fail is `verdict_failed` for the lead and nothing is pushed; a pass completes.
- Verdicts carry `tree`, `command_digest`, `tag` and `prev_command_digest`; the lease carries `snapshot`, `snapshot_command`, `snapshot_tag`; a verdict without a valid seal on the lease's sealed snapshot is no verdict.
- New owner-grant keys `verifier_timeout`, `verifier_output_limit`, `verifier_parallelism`, `verifier_goproxy`; `verifiers.<class>` takes a string or an argv list.
- The scheduler runs the commit step off its tick (`commit_running`, `commit_adopted`, `commit_cancelling`, `commit_cancelled`, the exits queue's `commit` entries with their `deferrals`); an interrupted verifier run defers as `verifier_interrupted`, and at the deferral limit the task blocks for the lead.
- The verifier has its own module cache under the session root; hook ledger lines are redacted on write (`redact.Block` over the whole value); malformed payloads are kept as a redacted prefix, not base64.
- An attempt archives an unsealed verdict as `invalid`; routing reports `verifier_result: invalid` for it.
- CleanSeat reserves the seat (`seat_reserved`) instead of holding the store lock across its git work; redaction of capped text follows the cap rule (`redact.Capped`).
- A gated class with no verifier command is never dispatched (`grants_invalid`).
- guard denies a seat's `amq-squad seat commit` and `scheduler run` (`harness_only`); `seat commit` refuses inside a seat.
- Status attention `verifier_waiting`; the evidence ledger gains `harness_verifier` lines.
- doctor's R12 line counts its predicate verdicts and says they are unsealed.
