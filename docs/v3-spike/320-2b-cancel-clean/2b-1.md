## The change, item by item

**1. The cancel's clean, in the seat's exit path.** `scanAttemptsLog`
(`internal/scheduler/exits.go`) queues an exit item for a cancelled
attempt (`Why: cancelled`, `TaskAttempt`) once per attempt. When the
attempt is the seat's last lease (no later lease, the occupant match of
A) the item carries `Close`, and `runExits` marks a seat the scheduler
counts up `closing: task_cancelled` and waits: `closeIdle` closes it through
the launcher (an `AsyncCloser` waits for its `seat_gone`), `holdForExit`
reserves the slot and clears `Close`. Only then the check runs
(`ExitCheck`, 0c-A's evidence) and `CleanAttempt`
(`schedproc.CleanSeats`: `ArchiveAttemptReason` under the task and
attempt with the outcome as the reason, then `CleanSeatDetailed`). A
finished clean is written on the attempt (`CleanedAt`,
`task.MarkAttemptCleaned`) before the one decision line
(`seat_cleaned`: "seat dev's work on t64 attempt 2 was archived and its
worktree cleaned"). The slot is released after that, by the existing
`releaseDecided` (nothing pending for the seat).

**2. The roster plan's own dirty-worktree check.** `slots.go`'s
`cleanWorktree` runs before `moveWorktree`: `update-index --refresh`
through the hardened git (stat data only), then `diff-index --name-only
HEAD` and `ls-files --others --exclude-standard`. A tree clean after the
refresh proceeds; when the refresh changed the index the plan logs
`seat_index_refreshed` once ("seat reviewer's index was stale;
refreshed"; `Slots.LogDecision`, wired in `scheduler_run.go`). A tree
still dirty refuses `seat_worktree_dirty: seat c1: the worktree has
local changes`, with no git text; a listing that fails is
`seat_worktree_check_failed` (its constant `ReasonSeatWorktreeCheckFailed`,
so the words scan sees it). git's text appears below the rule only when
`read-tree` itself fails on a tree the check called clean.

**3. `amq-squad seat clean --seat H`** (`internal/cli/seat_commit.go`,
`runSeatClean`) is a lead verb through the scheduler's decision socket
(item 9): the CLI reads the launch record and sends `CleanRequest`
(`amq-squad.clean.v1`, `schedproc.SendClean`); the scheduler proves the
sender (`not_lead`, `origin_unknown`, `scheduler_starting` as for `task
widen`) and `manualCleanDecision` (`process.go`) refuses in words while
the seat holds a lease ("seat dev is still running (it holds t64); stop
it first") or its process runs by the liveness check ("seat dev is still
running; stop it first"; an unreadable liveness is
`seat_liveness_unknown`), the code below the rule; else
`CleanSeats.CleanStopped` archives the seat's latest ended attempt
(`latestEndedAttempt`, the rule in G) and cleans. The clean callback
shares the process's mutex with `Tick`.

**4. The cleaner marker** (`internal/task/unclean.go`) records the
cleaner's pid and start stamp. `ReserveSeatWithDecision`: a marker whose
process is alive with that stamp refuses `seat_cleaning` with the
marker's age, whatever the age; a marker whose pid is dead or reused is
taken over at once with one decision (`cleaner_marker_taken_over`, logged
by the prepare, the cancel clean and `seat clean`); the TTL stays only
for a marker whose identity cannot be read (no pid, or a live pid whose
stamp is unreadable). `ReleaseSeat` runs as a defer on every path of
`CleanSeatDetailed`.

**5. A worktree on a cancelled or foreign task branch, or a detached
HEAD,** is moved to the seat branch by the clean itself (`cleanSeat`,
`onTask`): the old refusal for a branch the ledger's lease does not name
is gone (`Ledger.knownBranch` removed with it). Untracked and modified
files are archived first (the discard), then the move. One guard: a
commit on HEAD that `rev-list rest..HEAD` shows and that is neither the
resting commit nor on the ledger's commits refuses
`seat_head_detached_unmerged` (now the constant
`seatcommit.RefusalSeatHeadDetachedUnmerged`, the same code and words as
`slots.go`'s), said once (C), the marker released, the worktree and its
branch untouched; the branch itself is never deleted by the clean.

**6. A cancel under a tampered ledger** quarantines (0c-A, at the exit
check's `ReadLedgerAs`) and refuses `ledger_tampered`; the item stays
queued as the hold (D); no discard, no clean, the worktree untouched.

**7. Words.** `words.ts`: `seat_worktree_dirty`,
`seat_worktree_check_failed` and `slots.go`'s other `Reason*` codes in
`LAUNCH_WORDS`; `seat_head_detached_unmerged` in `BLOCK_WORDS`;
`seat_clean_deferred` a stop in `DECISION_WORDS`; `seat_index_refreshed`,
`cleaner_marker_taken_over` and `seat_clean_superseded` routine. The
scans (note 3) now read `internal/schedproc/slots.go` and the constants.

**8. Every attempt end that skips `CleanSeat`** is listed in

## Codex's findings on 71766f44, as built

**A (P1, exits.go:362).** Both halves, as the plan reviewer's note 1
requires. The occupant match: a cancelled attempt is the seat's
unresolved cancellation only while the seat has no later lease (ended or
current, `laterLease`); one superseded by a later lease was cleaned at
that lease's boundary (the prepare's `CleanSeat` before the grant), so

and the seat, which may be on another task, is neither closed nor
cleaned for it. The close (Codex's P1 on #909, `exits.go:394` at
`fb50818a`): a cancelled attempt that is its seat's last lease, with no
exit item yet, is close-required, every time. Nothing the scheduler holds
proves the seat stopped working on it: a restart has seen no lease held
(a cancel that lands before the previous incarnation queued its item
leaves no `Close` on disk, and the new incarnation adopts the live
roster seat as up), and the lead's `dispatch` (`internal/cli/dispatch.go`)
grants a lease outside the tick, so a "seen held" record misses it too.
The earlier gate (`held`, the leases at the end of the previous tick,
`rememberHeld`) is removed with the field: its no-close branch was the
P1's adopt-and-clean path. `runExits` closes a seat the scheduler counts
up and waits for the confirmed close (`closeIdle`, the launcher's close,
an `AsyncCloser`'s `seat_gone`) before the check and the clean; a seat it
does not count has nothing to close (a restart adopts every live seat the
launch ledger proves, up or closing, before its first tick, and a seat
this incarnation launches is counted from its `seat_up`). Whatever the
close path, the clean itself waits for the seat's launch identity to be
seen gone (the plan reviewer's rule on #909): "confirm termination" is the
accepted proof's pid and start stamp gone, never a pid alone (pids are
reused). `seatIdentityGone` asks the scheduler's `Liveness`
(`schedproc.Liveness.SeatProcess`, the launch ledger's proof): a pid that
now carries another start stamp, or no process at that pid, is gone; a
pid alive with its stamp, alive with a stamp that cannot be read, a
proof that is missing or unreadable, or no liveness hook at all is not
gone. Not gone fails closed: nothing is archived or cleaned, the item and
the seat's hold stay queued, the attempt stays uncleaned, and the lead
gets one stop (`seat_may_be_writing`, code `seat_identity_unproven`:
"seat H may still be writing to its worktree; the lead runs seat clean
after it stops"), once per (code, seat, task, attempt); the next ticks
re-read the identity silently and clean once it is seen gone. This covers
the seat a restart never adopted because its identity could not be read
(`LiveSeats` skips it), the case the "nothing to close" rule alone would
have cleaned. Limit, stated: an identity that stays unreadable keeps the
seat held; the lead's `seat clean` reads the same identity and refuses
`seat_liveness_unknown` while it does, so the lead clears the cause (the
proof, or the process) first. The cost, stated:
a parked roster seat whose last lease is an uncleaned cancellation (an
old one from before `cleaned_at`, or one a downgrade stripped) is closed
once at the next restart and relaunched by the roster; a seat with a
later lease, t64's and t86's shape, is never closed or cleaned for it
(`seat_clean_superseded`). The flag is persisted on the exit item
(`Close`), so a restart finishes a close the previous incarnation began,
and cleared at the confirmed close (P2-c's row). The durable record:
`CleanedAt` on the attempt in the task store, set by `MarkAttemptCleaned`
when the clean finishes, read by `scanAttemptsLog` before acting; a
cancellation the restart finds unrecorded is closed (when its seat is
up) and completed once. A persisted item is reconciled with the record
before anything acts (Codex's P2-a on #909, `exits.go:450`): a crash
after `MarkAttemptCleaned` and before the deferred exits-ledger write
leaves the item queued on disk; `dropRecordedCleans`, at the start of the
scan, drops an item whose attempt carries `cleaned_at`, with one line
(`seat_clean_replay_dropped`), writes the queue without it and releases
the slot it held; the clean does not run again.

## Compatibility with older readers

The struct diff of this PR against `origin/v3` (`git diff origin/v3 HEAD`,
every added or changed `json` tag in the declared files):

```
internal/task/task.go (Attempt):
+	CleanedAt *time.Time `json:"cleaned_at,omitempty"`
internal/task/unclean.go (seatMarker):
+	PID   int       `json:"pid,omitempty"`
+	Start string    `json:"start,omitempty"`
internal/seatcommit/ledger.go:
-func (l Ledger) knownBranch(ref string) bool { ... }   (a method, no field)
```

1. No sealed structure gains a field. The commit ledger's structs
   (`Ledger`, `LedgerDiscard` and the rest of `ledger.go`'s types) are
   byte-identical to `origin/v3`'s and to `v3.1.2`'s. `ledger.go` only
   loses `knownBranch`. The task store's seals are `verdictBody` and
   `snapshotBody` in `internal/task/verdict.go`. They carry explicit
   fields (task, attempt number, holder, tree, the command digest; the
   verdict's also verifier, result, source, detail and time), never the
   `Attempt` struct. They are identical at `v3.1.0-rc.1`, `v3.1.2` and
   this head. So the new `Attempt.CleanedAt` is outside every seal.
   The ledger's seal is checked over a re-encode of the decoded struct
   (`ReadLedgerAs`: `sealed := l; sealed.Seal = nil`, then
   `sealchain.Check`). So the v3.1.2 binary raises no `ledger_tampered`
   on a ledger this build wrote, and neither does v3.1.1, whose structs
   are the same.
   The limit, which predates this PR: `v3.1.0-rc.1`'s `LedgerDiscard`
   has no `Attempt` (`json:"attempt,omitempty"`, added in 3.1.1 by #853).
   A v3.1.0-rc.1 binary re-encodes a discard with a nonzero attempt without
   the field, and the tag fails (`ledger_tampered`). This build's
   cancellation archive writes exactly such discards (`commit.go:581`,
   `:687`), as 3.1.1's and 3.1.2's archives already did. A downgrade to
   v3.1.0-rc.1 is refused on such a ledger, by v3.1.1's addition, not this PR's.
2. The unsealed additions and what a downgrade does to them. The task
   store is one file per task (`tasks/<id>.json`) plus the journal
   `.transaction.json`, the same layout at `v3.1.0-rc.1` and `v3.1.2`.
   Their `Attempt` has no `cleaned_at`, and no decode in `internal/task`
   refuses an unknown field. An older binary reads a task file with
   `cleaned_at` and ignores it. When it rewrites that task's file (any
   mutation of the task: a commit writes each changed task whole), or
   replays a journal this build wrote, it drops `cleaned_at` from that
   task's attempts. After such a downgrade and a re-upgrade, a scheduler
   restart can see an old cancellation with no `cleaned_at`. Both halves
   of the occupant match then hold. If the seat has a later lease (ended
   or current: `laterLease`), the cancellation is recorded cleaned
   (`seat_clean_superseded`), and the seat is neither closed nor
   cleaned for it. If the seat has no later lease, the cancellation is
   close-required (Codex's P1 on #909): a seat the scheduler counts up
   is closed and its close confirmed, then the clean runs once (a parked
   roster seat is relaunched); a seat with no live process is cleaned
   once with nothing to close, after its launch identity is seen gone (an
