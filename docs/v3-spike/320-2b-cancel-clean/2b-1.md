## The change, item by item

**1. The cancel's clean, in the seat's exit path.** `scanAttemptsLog`
(`internal/scheduler/exits.go`) queues an exit item for a cancelled
attempt (`Why: cancelled`, `TaskAttempt`) once per attempt. `cancelRound`
calls `Store.ReserveCancel`, which reads later leases and takes the seat's
cancel reservation under the store lock, then acts outside the lock. A
later lease drops the item before anything acts. Otherwise a counted seat
is closed under the reservation; an `AsyncCloser` waits for `seat_gone`.
On a later round the exit check runs (`ExitCheck`, 0c-A's evidence), the
launch identity must be gone, and `CleanAttempt` calls
`ArchiveAttemptReason` followed by `CleanSeatHeld`. Every round defers
`ReleaseSeat`. A finished clean is written on the attempt (`CleanedAt`,
`task.MarkAttemptCleaned`) before the one decision line
(`seat_cleaned`: "seat dev's work on t64 attempt 2 was archived and its
worktree cleaned"). The slot is released after that, by the existing
`releaseDecided` (nothing pending for the seat).

**2. The roster plan's own dirty-worktree check.** `slots.go`'s
`cleanWorktree` runs before `moveWorktree`: `update-index --refresh`
through the hardened git (stat data only), then `diff-index --name-only
HEAD` and `ls-files --others --exclude-standard`. A tree clean after the
refresh proceeds; when the refresh changed the index the plan logs
`seat_index_refreshed` once ("seat reviewer's index was stale;
refreshed"; `Slots.LogDecision`, wired in `scheduler_run.go`). A tree
still dirty refuses `seat_worktree_dirty: seat c1: the worktree has
local changes`, with no git text; a listing that fails is
`seat_worktree_check_failed` (its constant `ReasonSeatWorktreeCheckFailed`,
so the words scan sees it). git's text appears below the rule only when
`read-tree` itself fails on a tree the check called clean.

**3. `amq-squad seat clean --seat H`** (`internal/cli/seat_commit.go`,
`runSeatClean`) is a lead verb through the scheduler's decision socket
(item 9): the CLI reads the launch record and sends `CleanRequest`
(`amq-squad.clean.v1`, `schedproc.SendClean`); the scheduler proves the
sender (`not_lead`, `origin_unknown`, `scheduler_starting` as for `task
widen`) and `manualCleanDecision` (`process.go`) refuses in words while
the seat holds a lease ("seat dev is still running (it holds t64); stop
it first") or its process runs by the liveness check ("seat dev is still
running; stop it first"; an unreadable liveness is
`seat_liveness_unknown`), the code below the rule; else
`CleanSeats.CleanStopped` archives the seat's latest ended attempt
(`latestEndedAttempt`, the rule in G) and cleans. The CLI refuses before
that path when no scheduler runs (`internal/cli/seat_commit.go:92`). The
clean callback is wired only by `internal/schedproc/process.go:263` under
the same `schedulerMu` as `Tick`, so a live scheduler's own cancel marker
cannot meet its own socket clean; a second scheduler is refused by
`run.lock` at `process.go:101`. P12's cross-process helper calls
`ReserveCancel` directly as a fixture for `cancelRound`: DEAD represents a
scheduler crash inside that round. LIVE has no product path while
`run.lock` holds. Read, not measured: `flock.ErrUnsupported` falls through
without a lock at `process.go:101`, so two schedulers can run on a
filesystem without flock; the live-holder guard remains for that case.

**4. The cleaner marker** (`internal/task/unclean.go`) records the
cleaner's pid and start stamp. A cancel-round marker also records
`Cancel: task#attempt`. `ReserveSeatWithDecision`: a marker whose
process is alive with that stamp refuses `seat_cleaning` with the
marker's age, whatever the age; a marker whose pid is dead or reused is
taken over at once with one decision (`cleaner_marker_taken_over`, logged
by the prepare, the cancel clean and `seat clean`); the TTL stays only
for a marker whose identity cannot be read (no pid, or a live pid whose
stamp is unreadable). `ReleaseSeat` runs as a defer on every path of
`CleanSeatDetailed` and every scheduler cancel round.

**5. A worktree on a cancelled or foreign task branch, or a detached
HEAD,** is moved to the seat branch by the clean itself (`cleanSeat`,
`onTask`): the old refusal for a branch the ledger's lease does not name
is gone (`Ledger.knownBranch` removed with it). Untracked and modified
files are archived first (the discard), then the move. One guard: a
commit on HEAD that `rev-list rest..HEAD` shows and that is neither the
resting commit nor on the ledger's commits refuses
`seat_head_detached_unmerged` (now the constant
`seatcommit.RefusalSeatHeadDetachedUnmerged`, the same code and words as
`slots.go`'s), said once (C), the marker released, the worktree and its
branch untouched; the branch itself is never deleted by the clean.

**6. A cancel under a tampered ledger** quarantines (0c-A, at the exit
check's `ReadLedgerAs`) and refuses `ledger_tampered`; the item stays
queued as the hold (D); no discard, no clean, the worktree untouched.

**7. Words.** `words.ts`: `seat_worktree_dirty`,

## Codex's findings on 71766f44, as built

**A (P1, exits.go:462).** The occupant match and the close now meet in
one reserve-then-act cancel round. `scanAttemptsLog` queues every
unrecorded cancelled attempt. `task.Store.ReserveCancel` then reads the
leases under the store lock. A later lease, current or ended, drops the
item before any close, check or clean and logs `seat_clean_superseded`.
Otherwise the same locked mutation takes the durable seat marker, naming
the cancelled task and attempt. The store lock is released before the
launcher close, exit check, identity proof and clean. A deferred
`ReleaseSeat` removes the reservation on every return path.

Every grant sees the reservation inside its store mutation. Both
`Grant` and `GrantClean` return `task.ReservedSeatError` in the exact
words "seat H is being closed and cleaned; dispatch again after it
finishes". The scheduler logs a reservation refusal through `logOnce`:
one `seat_prepare_failed`, one `seat_prepare_suppressed`, then counts
silently until the task, seat or reason changes. `preparePassed` runs
after the reservation check but before verifier and other grant errors.
Thus a reservation preserves the repeated-prepare count, while every other
grant result clears it. A scheduler crash leaves the marker with its pid and
start stamp; the next scheduler proves that pid dead, takes the marker over
and logs `cleaner_marker_taken_over` once.

The lead dispatch has a scheduler-liveness compatibility boundary. It
reads `taskSchedulerLive` once. With a live scheduler, it performs the
early `DispatchRefusal` before task creation and grants through
`GrantClean`, so a cancellation that lands between the read and the
grant is still refused. With no live scheduler, it skips the early
uncleaned-cancellation refusal and uses `Grant`, preserving the old
direct-dispatch compatibility path. D2 reaches only the grant-side
`seatLeasable` check, not the early uncleaned-cancellation refusal. The exact
superseded-drop exception and its future work item are recorded once under
**Limits**. `TestGrantCleanAllowsASeatThatWorkedPastAnUncleanedCancellation`
names its no-later-lease side,
`TestGrantCleanRefusesAnUncleanedSeatInsideItsMutation`; together with
`TestRestartDropsAQueuedCloseWhoseSeatHoldsALaterLease`,
`TestRestartDoesNotReplayOldCancellationOverNewOccupant` and
`TestDispatchWithNoLiveSchedulerKeepsTheCompatGrant` cover the same
`LaterLease` construction at the store, queued-exit, restart and CLI
boundaries. The old 3d once-per-seat approach could not distinguish that
later work from the cancelled attempt, so it could replay the old clean over
the new occupant. The four carried P9 proofs are
`TestRestartDoesNotReplayOldCancellationOverNewOccupant`,
`TestCancelDuringARunningStepFreesTheSeat`,
`TestDispatchPreparesAForeignBranchWorktreeThroughCleanSeatsAndGrants` and
`TestUntrackedOnlyCancellationIsArchivedCleanedAndSeatCanBeGranted`.

Separately, 3d984371 had the same once-per-seat prepare-count flaw even with
a preparer installed: `preparePassed` cleared the prepare-failure count before
the reserved grant check, so a reserved seat's refusal was logged every tick.

A close-required attempt on a counted seat is closed while the marker is
held. A confirmed close clears `Close`, records `Gone`, and leaves the
item queued for the next round. `CleanAttempt` archives the task and
attempt, then calls `seatcommit.CleanSeatHeld`, which uses the already
held reservation rather than taking a second marker. A seat this
scheduler does not count has nothing to close. In either case the clean
still requires the launch identity's pid and start stamp to be seen
gone. Missing, unreadable or live proof fails closed with one
`seat_may_be_writing`; the item, slot hold and uncleaned attempt remain.

Between rounds the reservation is absent by design. The queued exit item
keeps the scheduler from granting the seat, while a live scheduler's
lead dispatch refuses the unresolved cancellation in the exact
`UncleanedSeatError` words. A failed clean therefore leaves no marker,
keeps the item in memory and in the sealed exits ledger with its
`Close:false, Gone:true` state, survives a scheduler restart, and is not
re-logged while the deferred reason is unchanged.

The durable success record remains `Attempt.CleanedAt`. The scan reads it
before acting. `dropRecordedCleans` removes a persisted replay whose
attempt already carries the record, writes the queue without it and
releases any slot it held, so a completed clean is not repeated. A
parked roster seat closed for its last uncleaned cancellation waits for
the lead's roster relaunch. A close already sent to an asynchronous
launcher cannot be called back; revalidation prevents any later close or
clean once the later lease is visible.

**B (P2, prepare.go:97).** The clean never removes bytes the ledger does
not hold: `cleanSeat` counts an attempt's earlier discard only when its
tree is the tree about to be removed; a worktree edited since gets a
second discard under the same task and attempt at its own time (the
sequence is the ledger's order and `At`). `ArchiveAttemptReason` keeps
the first writer per task and attempt (the typed widen's dry run reads
the snapshot of the stop; fix 1b's row), so a retried clean's new bytes
are the clean's discard, not the archive's.

**C (P2, exits.go:428).** `seat_clean_deferred` once per (seat, task,
attempt, reason), silent until the reason changes or the clean runs
(`logCleanDeferred`); `seat_prepare_failed` once per (seat, task, reason)
(`prepareFailed`); the hold's `exit_refused` and its lead notice once per
reason (`noteExitRefused`, keyed by the check's `ReasonCode`). The reason
is compared by its stable refusal code where one is present, never its whole
text (Codex's P2-b on #909:
`exits.go:560` and `scheduler.go:875` compared texts, and a live
cleaner's refusal, `unclean.go:171`, names its advancing age, "being
cleaned by pid N for 12s", so every tick read as a new reason).
`refusalCode` finds the first `": "`-separated segment that is a refusal
code (snake_case with an underscore: the store's sentinels
`seat_cleaning`, `seat_unclean`, and the clean's and the prepare's refusals
all lead with theirs, wrapped or not). `reasonIdentity` instead masks paths
and digit runs for untyped failures. The decision line still carries the
first full text.

**D (P2, exits.go:435).** The hold is the seat's unresolved cancellation:
a refused cancelled item stays queued (persisted in the exits ledger), so
`exitPending` holds the slot against any other item's release and
`idleSeat` grants nothing to the seat, until the check passes and the
clean runs; the row tries a gone item and a competing grant during the
hold, then the repair that releases.

  The recorded-commit comparison: `recorded` is HEAD equal to the

- `PrepareSeat` callers: `scheduler.dispatch` is the one caller

## Compatibility with older readers

On the 0e raw layout, the sealed exits item gains `task_attempt` and `close`
at schema 1. Both are `omitempty`. An rc.1 legacy item, or a raw item with
neither field, therefore reads on both builds. A build between #925 and this
change refuses a raw exits item carrying either field as `schema_mismatch`
and stops dispatch for the lead. No released build wrote the raw layout
before rc.2, so rc.2 ships the complete schema-1 field set. After rc.2 is
tagged, every new sealed field must bump the schema.

The struct diff of this PR against `origin/v3` (`git diff origin/v3 HEAD`,
every added or changed `json` tag in the declared files):

```
internal/task/task.go (Attempt):
+	CleanedAt *time.Time `json:"cleaned_at,omitempty"`
internal/task/unclean.go (seatMarker):
+	PID   int       `json:"pid,omitempty"`
+	Start string    `json:"start,omitempty"`
+	Cancel string   `json:"cancel,omitempty"`
internal/scheduler/exits.go (exitItem):
+	TaskAttempt int  `json:"task_attempt,omitempty"`
+	Close bool       `json:"close,omitempty"`
internal/seatcommit/ledger.go:
-func (l Ledger) knownBranch(ref string) bool { ... }   (a method, no field)
```

1. The commit ledger gains no field. Its structs
   (`Ledger`, `LedgerDiscard` and the rest of `ledger.go`'s types) are
   byte-identical to `origin/v3`'s and to `v3.1.2`'s. `ledger.go` only
   loses `knownBranch`. The task store's seals are `verdictBody` and
   `snapshotBody` in `internal/task/verdict.go`. They carry explicit
   fields (task, attempt number, holder, tree, the command digest; the
   verdict's also verifier, result, source, detail and time), never the
   `Attempt` struct. They are identical at `v3.1.0-rc.1`, `v3.1.2` and
   this head. So the new `Attempt.CleanedAt` is outside every seal.
   The ledger's seal is checked over a re-encode of the decoded struct
   (`ReadLedgerAs`: `sealed := l; sealed.Seal = nil`, then
   `sealchain.Check`). So the v3.1.2 binary raises no `ledger_tampered`
   on a ledger this build wrote, and neither does v3.1.1, whose structs
   are the same.
   The limit, which predates this PR: `v3.1.0-rc.1`'s `LedgerDiscard`
   has no `Attempt` (`json:"attempt,omitempty"`, added in 3.1.1 by #853).
   A v3.1.0-rc.1 binary re-encodes a discard with a nonzero attempt without
   the field, and the tag fails (`ledger_tampered`). This build's
   cancellation archive writes exactly such discards (`commit.go:581`,
   `:687`), as 3.1.1's and 3.1.2's archives already did. A downgrade to
   v3.1.0-rc.1 is refused on such a ledger, by v3.1.1's addition, not this PR's.
2. The unsealed additions and what a downgrade does to them. The task
   store is one file per task (`tasks/<id>.json`) plus the journal
   `.transaction.json`, the same layout at `v3.1.0-rc.1` and `v3.1.2`.
   Their `Attempt` has no `cleaned_at`, and no decode in `internal/task`
   refuses an unknown field. An older binary reads a task file with
   `cleaned_at` and ignores it. When it rewrites that task's file (any
   mutation of the task: a commit writes each changed task whole), or
   replays a journal this build wrote, it drops `cleaned_at` from that
   task's attempts. After such a downgrade and a re-upgrade, a scheduler
   restart can see an old cancellation with no `cleaned_at`. Both halves
   of the occupant match then hold. If the seat has a later lease (ended
   or current: `laterLease`), the cancellation is recorded cleaned
   (`seat_clean_superseded`), and the seat is neither closed nor
   cleaned for it. If the seat has no later lease, the cancellation is
   close-required (Codex's P1 on #909): a seat the scheduler counts up
   is closed and its close confirmed, then the clean runs once (a parked
   roster seat is relaunched); a seat with no live process is cleaned
   once with nothing to close, after its launch identity is seen gone (an
   unreadable one fails closed, the identity rule in A)
   (`TestRestartFinishesUncleanedCancellationOnceAndPersistsIt`'s case),
   and B's tree check adds no discard when the tree is the one already
   archived. A busy seat (one on a later lease) is never closed by it. The marker
   (`tasks/reserved/<seat>`): an older binary's `seatMarker` decodes
   `nonce` and `at` and ignores `pid` and `start`, so it judges every
   marker by age alone (its rule: fresh under `SeatReservationTTL`, 10
   minutes, refuses; older is taken over). This build reads a marker
   with no `pid` or `start` (an older binary's) as an unreadable
   identity, which is the TTL path: refuse under the TTL, take over
   after it.

### Limits

- The no-live-scheduler compatibility grant is intentionally unpinned. When
  it lands after an old cancellation, the later lease makes that cancellation
  superseded and the scheduler records `cleaned_at` even though no clean ran.
  The next preparation remains responsible for archive and worktree safety.
  A future release should record "superseded, nothing cleaned" separately.
  The same item appears by name under **The 3.2.0 list** below.
- A reserved seat still pays the PrepareSeat cost before the locked grant
  returns `ReservedSeatError`. Meeting 5 proves the refusal is logged once and
  counted; moving `preparePassed` before the grant fails its suppressed-count
  assertion. Moving the reservation check ahead of preparation would require
  a new store/scheduler contract and is outside this no-behavior-change round.
- Against the base, one task can cost one prepare per failing seat in its pool
  per tick as the scheduler skips through the pool, with each distinct failure
  logged once. `TestTypedRefusalExcludesWhileAPlainRefusalLogsOnce` is the
  revert row for that cost and suppression boundary.
- P11 remains a persisted-ledger and forward-compatibility row. The current
  product API cannot create a second attempt after cancellation because
  cancellation is terminal and Reset accepts blocked tasks only.

The round's sole product edit is the corrected comment on
`preparedIdleSeat`: the form carried by `683b8479` falsely said a task is
never blocked for another seat's ledger, but a tamper is returned as that
task's typed block. The replacement comment names the typed exclusions, the
tamper stop and the retry behavior without changing code.

The existing bounded rows wait 2 seconds at the two exits909 sites and poll
up to 5 seconds in the seatcommit cancellation fixture. The gate's own form
passed 6 of 6 on the host on 2026-11-10, taking 305 to 338 seconds; no timeout
changed in this round.

### Release note

A cancelled seat is now closed, its work archived and its worktree cleaned
before the slot is released. Leads can run `amq-squad seat clean` for a
stopped seat. Roster planning refreshes a stale index and refuses a dirty seat
worktree in plain words. A dead cleaner's marker is taken over immediately.
