# t49: strict up-to-date merge policy

The merge train now reads GitHub's effective strict required-status-checks policy. A strict, behind PR is planned for rebase regardless of its current CI result, then the real run uses the existing audit, rebind, CI wait, re-check, and pinned merge path. A conflict or binding drift is refused during planning with `strict_required_status_checks_policy`, so dry run does not promise a merge that GitHub will reject.
