# 3.2.0-2a claim offer evidence

## Result

`task claim` selects one of two paths through `taskSchedulerLive`. A live
scheduler is proved only by its launch record's PID still being alive with the
same raw process-start stamp. On that path an ID claim acknowledges only the
live, unclaimed offer for the same holder, while a claim without an ID is
refused in words: “the scheduler hands out work; wait for its offer”. A missing
record, a gone PID, or a mismatched start stamp takes the compatibility path.

The compatibility path calls `Store.ClaimServing`. Selection, `PoolServes`,
and grant/claim happen in one locked update. A `task set --pool` that commits
after a caller's old read and before the claim is therefore seen and refused.
A known seat pool can claim only work it serves. An unknown seat pool fails
closed on pinned work with `claim_pool_unknown` and the words “ID is pinned to
POOL; claim it with --pool, or let the scheduler hand it out”; an unpinned task
remains claimable. Pull-next uses the same in-lock filter and never selects a
task pinned to another pool.

Pool admission belongs to the claim verbs. A claim checks the seat's serving
pool and never moves an existing routing decision. `Store.Grant` is the
scheduler router's writer: after a failed attempt escalates, the next grant
records the new tier's pool instead of refusing it against the previous
attempt's pool.

A readable seat launch record supplies a claim pool only while its exec PID is
alive with the recorded raw start stamp. A gone PID, a PID with no stamp, and
no record all leave an explicit `--pool` authoritative. When a live record and
`--pool` disagree, the CLI refuses the mismatch in words.

A lapsed holder is excluded for the current seat launch only. Scheduler
adoption reads the seat's published `launch.Record.StartedAt`; scheduler
restart time never becomes `joinedAt`. A real seat relaunch writes a later
`StartedAt` and clears the old exclusion. Runtime activity cannot renew an
offer whose `claimed_at` is absent. Adoption fails closed when the record is
unreadable or its `StartedAt` is zero: `joinedAt` remains zero, so a lapsed
attempt remains excluded.

The CLI-only refusal names are `claim_offer_required`,
`claim_offer_expired`, `claim_pool_mismatch`, and `claim_pool_unknown`. Their
complete plain words are emitted by the Go CLI above the refusal rule. They
are not persisted task block reasons, so the three unreachable claim entries
were not added to `BLOCK_WORDS`; the row-7 scan still covers every actual wait
and block name.
