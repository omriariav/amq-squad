# 3.2.0-2a claim offer evidence

## Result

An ID claim acknowledges work only when a live scheduler has already offered
that task to the same seat. The offer must still be live and the seat pool must
serve the task pool. A claim can fill an unpinned task pool, but it never
rewrites an existing pool. Without a live scheduler, the compatibility path
still permits a serving pool and refuses a non-serving pool.

A lapsed holder is excluded for the current seat join only. A later `SeatUp`
starts a new incarnation and makes the seat eligible again. Runtime activity
cannot renew an offer whose `claimed_at` is absent.

The new refusal codes are `claim_offer_required`, `claim_offer_expired`, and
`claim_pool_mismatch`. Their owner-facing words are mapped in the one Pi words
table; the raw code remains below the rule.
