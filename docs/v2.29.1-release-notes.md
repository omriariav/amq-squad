# amq-squad v2.29.1

## Summary

v2.29.1 is a patch release: mid-run member adds now arrange the lead's
current window as `main-vertical` by default, with the lead guaranteed to
occupy the full-height main pane. It also ships the dynamic-membership field
gotchas learned from the first v2.29.0 live run into the orchestrator skill.

## Lead-main window layout on mid-run member adds (#664)

Before: a mid-run `team member add --launch` / `resume --exec` split the
lead's window with no layout pass at all, so each added worker halved
whatever pane happened to be active — after two or three adds the lead was
squeezed into an unusable sliver.

Now, when the mid-run member-add signature holds (orchestrated team, target
`current-window`, no explicit `--layout`, lead already live), the window is
arranged as `main-vertical`: the lead keeps a full-height left column (60%
of the window width, best-effort) and added workers stack in rows to its
right.

The arrangement is verified, not assumed — hardening from the codex review
gate (two rounds, final verdict APPROVE):

- **The lead is guaranteed to be the main pane.** `select-layout` assigns
  the main slot by pane order, and the splits leave the last-added worker
  active, so the main pane is resolved by geometry (the single pane in
  column 0) afterwards; when a worker landed there, the lead is swapped in,
  the result is verified with an identity-echoed probe, and focus is
  restored to the lead.
- **The arrangement requires real lead identity.** The dependents-only
  resume path applies the layout only when the lead launch record's pane id
  equals the invoking `$TMUX_PANE`, fail-closed on any missing side — a
  resume issued from an operator shell or a worker pane never rearranges
  the caller's window, and `--skip-lead-check` (which verifies no lead at
  all) always skips the arrangement.
- **Failures leave no residue.** The window's `main-pane-width` is
  snapshotted as a LOCAL option before mutation; a failed launch restores
  the prior value verbatim (or unsets a previously-unset option), and when
  the snapshot itself fails the best-effort width is skipped entirely —
  a mutation whose baseline is unknown cannot be undone.

Explicit `--layout` always wins: the arrangement is a default, not an
override.

## Dynamic-membership field gotchas in the orchestrator skill (#663)

The orchestrator LEARNINGS gained the traps hit in the first hour of the
first v2.29.0 live squad:

- **Implementation grants collide silently on the mid-run path.** `member
  add` + `resume --exec` runs no worktree-isolation preflight, unlike
  `start`; two implementation-mode seats in a shared cwd surfaced only via
  `doctor` as `worktree/shared-index-collision`. Default to `review`
  actor-mode for mid-run adds.
- **Bare `agent up` produces a ghost seat.** A seat launched with `agent
  up` directly, with no prior `member add`, runs with a mailbox, a pane,
  and a claimed task but no `team.json` entry — invisible to roster-scoped
  `member rm`/`update`/`resume`. (`member add` itself persists the roster
  entry before printing its `agent up` hint, so that path still leaves a
  rostered seat.) Squad seats go through the roster, always.
