# amq-squad v3.0.1

amq-squad 3.0.1 is a fix release on the 3.0 line. The module path is
unchanged:

```sh
go install github.com/omriariav/amq-squad/v3/cmd/amq-squad@v3.0.1
```

3.0.1 is the first dogfood's fix release. It is built from the first squad run
on the amq-squad repository itself, on 2026-10-30 (session v31), on the
installed 3.0.0 binary, and from what that run found: the squad could hold only
one live seat, seats idled after their first turn until someone typed in the
pane, Claude seats stalled on Claude Code's first-run screens, a seat's
`doctor --probe` rewrote the owner's registry, the commit step pushed a seat
branch without binding a PR, and a failed seat launch left no reason anywhere.
The items below were built outside the squad, by agents under the owner's
decision, each with the reviewer's read, a Codex pass and the lead's gate,
because the squad could not build them for itself. Upgrading from v2: see
[MIGRATION.md](../MIGRATION.md). The 3.0 notes are
[docs/v3.0.0-release-notes.md](v3.0.0-release-notes.md).

## The GPT-6 family in the Codex catalog (#803, brief 0)

- The Codex catalog carries the GPT-6 family as codex-cli 0.166.0 reports it:
  gpt-6.1-sol, gpt-6-sol, gpt-6.1-terra, gpt-6-astra and gpt-6-luna, with
  tiers mirrored from 5.6. gpt-5.6-luna is added as well.
- Each new model's cost tier mirrors its capability twin. The probe answers
  whether a model is usable, never what it costs.
- The registry's GPT-6 rows appear once the owner runs `doctor --probe` on the
  installed 3.0.1.

## The redact linearity test (#804, t7)

- The linearity test for `internal/redact` measures an in-process ratio
  between input sizes, interleaved, with one retry. It has no wall-clock bound,
  so machine load alone no longer fails it.

## doctor inside a seat (#805, t15)

- Inside a seat, `doctor` refuses `--probe`, `--write-registry` and `--fix`
  with `seat_owner_state_refused`, and skips the release-drift check. The owner
  runs them from their own terminal.
- The seat environment marker is a fence against a brief's mistake. It is not
  a fence against a seat that unsets its environment. That needs a seat-owned
  `AMQ_SQUAD_HOME`, which is 3.0.x work.

## The commit step binds the seat's PR (#806, t14)

- The scheduler's commit step opens and binds each pushed seat branch's draft
  PR by default when the repository has a merge grant, so the merge train can
  take it.
- `--no-open-pr` is refused under a merge grant. `--open-pr` is a no-op.

## Seats launch with AMQ wake (#807, t9)

- Seats launch with AMQ wake required, so the scheduler's doorbell is the
  seat's next turn.
- A Codex seat is woken when AMQ's Codex dialog hook entries are present and
  the seat worktree's trust line exists.
- A Claude seat is woken when its permission mode is dontAsk, the hooks guard
  denies AskUserQuestion and ExitPlanMode in a seat, and the startup screens
  are closed (#809).
- pi seats stay unwoken: AMQ's pi doorbell guard needs AMQ's pi extension.
- An unmet condition keeps the wake off with a named reason. `seat-exec`
  re-checks the guard on the real config dir, and admission evidence is
  required per seat.

## The Claude seat's config dir (#809, t6)

- A Claude seat's config dir is born past first-run onboarding
  (`hasCompletedOnboarding` and a theme), with its worktree trusted under
  NFC-normalized keys. The canonical repository root is refused by name. The
  hooks plugin is enabled.
- The Check is an allowlist of the launch's keys plus the pinned binary's
  bookkeeping sets, with the permission readers walked. Malformed inputs count
  as drift, and reads are by exact key.
- External CLAUDE.md includes keep the startup screens open, so such a seat
  stays unwoken.
- `claude_pin_mismatch` is reported when the claude binary differs from the
  pin.
- Every Claude seat's environment carries
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, recorded on the registry's
  Claude entries.

## The roster launch (#808, t16)

- The scheduler launches every seat in one AMQ prepare and apply at start.
  AMQ 0.116.2 refuses a fresh seat into a present binding, so in 3.0.0 a
  squad was single-seat.
- Idle seats are parked, and `max_seats` caps leases. A scheduler restart
  adopts the live roster seats.
- A gone seat blocks its task for the lead's `scheduler relaunch`. Relaunch
  refuses before Apply when a recorded pane still exists on the binding's
  server and session.
- The team-mode lead is proved from the scheduler's parent process, by pid and
  start stamp with each hop checked. The roster excludes the `--lead` handle.
- `lead --team --trust` passes the owner's standing trust through. A
  `trust_confirmation` without it refuses once at start.
- Two pi lead tools: `amq_scheduler_relaunch`, and `amq_task_widen` over the
  refusal's exact recorded paths, each as `task widen --path`.
- The proof marker is a compare-and-set on the launch, with restaging under
  the same lock and one cross-process lock on the proof log.

## The Buzz owner-script dry run (#810, t18)

- The dry run waits on the test relay's own signal, with one run budget and a
  reap of the whole process tree.
- The test's build runs with `GOPROXY=off`.

## A failed seat launch is a decision (#811, t17)

- A failed or unresolved seat launch is a `seat_launch_failed` decision with
  the stage, the AMQ reason code and the redacted detail. AMQ output passes
  through one chokepoint.
- `status` shows it in place of `seat_starting`. A repeat of the same reason
  blocks the task for the lead. Failures and blocks survive a restart.
- Each tick checks every live roster seat by its proved identity and posts
  SeatGone `process_exited`. A repeated or stale SeatGone is ignored, and the
  exit queue checks one gone attempt once.

## Owner steps before the first 3.0.1 run

1. Install by temp and rename: build or `go install` into a temporary
   directory, then rename the binary over the old one, so macOS sees a fresh
   inode.
2. Run `amq wake install-dialog-hook --harness codex`, then trust the
   `AMQ_DIALOG_HOOK` entries in Codex's `/hooks`.
3. Run `amq-squad doctor --probe` from the owner's own terminal, not from a
   seat.
4. Start the squad through
   `amq-squad lead --team --scheduler-seats FILE --trust`.
5. Run the owner rows named in the execution notes: the live two-seat row, the
   relaunch leg through the pi TUI, a Claude seat reaching a prompt with no
   screen, and whether the runtime creates the canonical-root entry.

## Recorded limits

- The plugin marketplace reads the repository's main branch; the 3.0.1 plugin
  is installable from it after v3 is merged to main.
- A pane that outlives its process leaves the roster unreplaceable until AMQ
  can join a fresh participant into a present binding (ask 20).
- A hand-started scheduler has no caller for `scheduler relaunch` or
  `task widen`.
- `seat-exec`'s wrapper bypasses AMQ's startup-dialog hold.
- A seat runs with the owner's HOME.
- A worktree with external CLAUDE.md includes keeps the Claude wake off.
- The squad's seats are Codex and Claude on macOS. Linux seats are
  unsupported, as in 3.0.
