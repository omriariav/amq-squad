# amq-squad v3.0.0

amq-squad 3.0 is a rebuild on the AMQ coop primitives: the v2 launch and
orchestration code is deleted, and the core is smaller, tighter and
security-first. The module path is `github.com/omriariav/amq-squad/v3`:

```sh
go install github.com/omriariav/amq-squad/v3/cmd/amq-squad@v3.0.0
```

The recorded limits, the same-UID boundaries, the open acceptance rows and the
design rationale live in [docs/v3-plan.md](v3-plan.md) (section 13 for the phase status, section 16.4 for the phase 5 items and open acceptance rows, section 7 for the security model and its recorded same-UID limits).
They are not restated here. Upgrading from v2: see [MIGRATION.md](../MIGRATION.md).

## Subtraction (phase 2a)

- The v2 launch, composer, status board and runtime-control code is deleted.
- Three hook verbs ship: `context`, `guard`, `evidence ingest`.

## Core (phase 2b)

- Task store with leases and pools, and a scheduler with request ids and
  launcher-confirmed cancellation.
- Status contract (schema 1) with the four buckets and argv actions.
- `seat-exec` with a scrubbed environment, identity at launch from the record,
  and a read-only identity proof.
- `squad.yaml` schema 1 with show, check, propose, apply and draft-rules
  through the digest flow.
- Runtime registry with full re-hash at launch, `amq-squad trust`, and the
  doctor trust rows.
- Class table, tier chains and `routing.yaml`; the outcome log is a signed
  hash chain with a weekly `routing report`.
- The harness commit step (`seat commit`), `task widen` over the scheduler
  socket, the growth gate, and `seat clear` with a signed clear record.
- `amq-squad scheduler run` supervised by `lead --team --scheduler-seats`.

## Security (phase 3)

- Grants schema with narrowing, a fail-closed insecure owner file, the
  `credential_change` class, and signed deny records.
- Core-written gate store with one-decision recovery; signed gates for the
  four typed classes.
- Merge train under the standing merge grant, with branch and tag protection
  checks.
- Release flow: draft at the approved commit, read back and re-read before
  publish, audited deletions, orphan recovery.
- Redaction (`internal/redact`) with the real-shape rule, used by the
  evidence and source scans.

## Faces (phase 4)

- Built-in pi package with hooks, native AMQ tools and the hold seam; the
  pi runtime is verified against an embedded digest at every launch.
- Claude Code hooks plugin: injects the seat context, maps guard verdicts to
  deny, ingests evidence, silent outside a seat.
- One lead-session entrypoint for squad leads and the operator, the fleet
  registry, `status --fleet --json`, and the mayor inside the fleet grant.
- Buzz attachment: gate questions carry the reply thread and squad identity,
  answers are verified in the raising squad's store, phone messages route to
  squad leads.

## Release (phase 5)

- `squad.yaml` final form and `migrate` from v2 profiles.
- Re-passes of the merged heads: the Codex findings are fixed, the commits
  ledger and exits queue are sealed, and every value under a credential name
  is redacted.
- Test hygiene: the merge-train race run is much faster; the PTY deadline
  derived from a measured warm-up; launch window closed through cleanup.
- Buzz-signed `seat clear` as the second factor for the owner proof.
- Uninstall for the Claude plugin, the runtime directory and the amq-remote
  approval hook.
- Plugin manifests and the fourteen skill files move to 3.0.0.

Manifest at the release commit: size of 3.0 is 77,852 lines (v2 rows kept plus 3.0 additions), from `scripts/manifest-check.sh --final`.
