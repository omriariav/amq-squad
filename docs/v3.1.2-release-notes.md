# amq-squad v3.1.2

These are the notes for the 3.1.2 release, a fix release built from the tip
of v3. The lead does not start on 3.1.0 or 3.1.1. 3.1.2 makes it start
again. Nothing else changes. The module path is unchanged.

```sh
go install github.com/omriariav/amq-squad/v3/cmd/amq-squad@v3.1.2
```

A `go install` build carries no embedded pi runtime. The binary the squad runs
is built from the tag by `scripts/build-pi-runtime.sh`, as the owner steps
below show. The earlier notes are
[docs/v3.1.1-release-notes.md](v3.1.1-release-notes.md) and the notes it
links.

## What broke

On 3.1.0 and 3.1.1, `amq-squad lead` exits as soon as it starts. pi prints
one error and the hint to start without extensions:

```
Error: Failed to load extension ".../pi/extensions/amq-squad.ts": Failed to load extension: ParseError: Identifier 'HostFacts' has already been declared.
 .../pi/extensions/lib/firstturn.ts:114:13
Hint: Start without extensions using "pi -ne".
```

The squad's pi extension gave two things one name in one file: a type and a
class, both `HostFacts`. Node, which ran the extension's tests, drops the
type and runs the file, so every test and `make ci` passed. pi's own loader
reads the file with Babel, which refuses a name declared twice, so pi stops
before the lead's first screen.

It is a 3.1.0 regression, from #837, first seen on 3.1.1. Nobody saw it on
3.1.0 because the squad kept running on 3.1.0-rc.1, which predates the file.
3.1.1 was the first build anyone started a lead on.

----------

**Records.** The type came in with `f95b70ab` and the class with `43933bc4`,
both in #837 on 2026-11-01. Neither is in 3.1.0-rc.1. The execution note is
[docs/v3-spike/312-evidence/hotfix-hostfacts.md](v3-spike/312-evidence/hotfix-hostfacts.md).

## The fix and the new test

- **The type has its own name.** It is now `ContextHost`, after the Go type
  it mirrors. The class keeps the name `HostFacts`. Nothing else changes.
- **The pi suite loads the extension the way pi does.** A new test file runs
  every extension file through pi's own transform, loads the extension
  through pi's own loader, and starts pi's bundled command line with the
  extension. That last run is offline, with no key, so pi stops at "No API
  key found" and calls no model. These three run in CI. A fourth runs the
  same start on a built runtime when one is on the machine, and skips with
  its reason when none is.
- **The test fails on the 3.1.1 file.** With the old file back, all four
  fail with pi's error, while the other 110 tests still pass.
- **The built lead starts.** `amq-squad lead --team`, built from this branch
  the way the release builds, shows its first screen and stays up. The same
  build with the old file dies with the error above in 3 seconds.

----------

**Records.** `pi/test/piload.test.ts`. The revert run, the two tmux
captures and the gates are in the execution note.

## The workaround on 3.1.0 or 3.1.1

Until you install 3.1.2, run the squad on 3.1.0-rc.1, the build the squad
ran on through both cuts. rc.1 lacks what came after it, such as 3.1.1's
screen in words and its commands. From the repository, put the
rc.1 build back with `up --binary`. It installs itself over the
`amq-squad` on PATH, then starts the squad:

```sh
cd ~/code/amq-squad
~/scratch-v31rc1/build/pi/amq-squad up --binary ~/scratch-v31rc1/build/pi/amq-squad
```

## A new step in the release cut

A release now counts as done only when the installed new binary starts the
lead. Either the squad's own lead restarts on it, or
`amq-squad lead --team` runs in a scratch repository. The release evidence
records the lead's first screen. `RELEASING.md` has the step (step 6). The
3.1.2 evidence is its first instance.

## Owner steps for 3.1.2

Install by temporary name and rename, from the tag, never from the working
tree (R54).

1. After the v3.1.2 tag is published, build the tag in a scratch worktree:

   ```sh
   git worktree add ~/scratch-v312 v3.1.2 && cd ~/scratch-v312 && scripts/build-pi-runtime.sh all
   ```

   The binary is `build/pi/amq-squad`.
2. From the repository, run `up` from the tag build:

   ```sh
   cd ~/code/amq-squad
   ~/scratch-v312/build/pi/amq-squad up --binary ~/scratch-v312/build/pi/amq-squad
   ```

3. Read the lead's first screen. The last line lists
   `/add  /reset  /dismiss  /answer  /widen  /team hide`. Record the screen in
   the 3.1.2 release evidence (RELEASING.md step 6).
