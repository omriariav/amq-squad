### Task schema fields that die with the verbs

The final retained `Task` shape is expected to be a flat record: identity,
title/description, plain status, assignee, dependencies, timestamps, and only
the minimum evidence the final `done` contract explicitly keeps. The groups
below are deletion candidates; ambiguous survivors are called out rather than
assumed.

| Schema group | Fields/types | Disposition and verb dependency |
|---|---|---|
| Extended statuses | `completed_pending_reconcile`, `failed`, `blocked`, `cancelled` | Delete with reconcile/fail/block/cancel; retain `pending`, `in_progress`, `completed`. |
| Transition reasons | `FailureReason`, `BlockReason`, `ResetReason`, `CancelReason` | Delete with their verbs. |
| Lease lifecycle | `Lease` (`Owner`, issue/renew/expiry/stale times), `ReleaseAudit`, `Releases` | Delete with `renew`/`release`; `AssignedTo` remains the plain claim owner. |
| Cancellation/replacement graph | `Replaces`, `ReplacedBy`, cancellation attention projection | Delete with `cancel`; no superseded state. |
| Delivery outbox | `Outbox`, `OutboxIntent`, `RetryAudit`, `ReceiptLink`, delivery states, message/receipt attempt/path fields, `LastError`, leadership epoch | Delete with `deliver`, `retry-delivery`, automatic completion notification, and the dropped delivery-intent atomicity guarantee. |
| Dispatch projection | `Dispatch`, `OutboxIntentID`, `DeliveryState`, receipt/message/path/error fields | Delete as task authority; AMQ is authoritative for the ordinary send. |
| Completion reconciliation | `CompletionReconcile`, `CompletionEvidence`, `CompletionEvidenceApply/Result`, `completed_pending_reconcile` | Delete with `reconcile`. |
| Completion gates | `CompletionLifecycle`, `CompletionGateCorrelation`, gate history/suppression, `NotificationSuppression` | Delete with task completion gates and automatic completion delivery. Human gates remain under top-level `gate`. |
| Lifecycle envelopes | `GenerationRef`, `LifecycleGenerationRef`, `LifecycleTaskGeneration`, `LifecycleEvents`, `LifecycleEnvelope`, `LifecycleEventRecord`, envelope hashes/evidence/outbox correlation | Delete with `event` and prepared-generation authority. |
| Task leadership | `LeadershipState`, `LeadershipHandoff`, `LeadershipEpoch` | Delete with `leadership`/`handoff`. |
| Review/replacement workflow | `ReviewOf`, `ReviewTasks`, `Reviewer`, `Implementer`, `ParallelWorkExplicit`, `FinalHead` | ruling_required: these exceed the flat four-verb contract, but some may be retained as inert metadata or moved to `verify` evidence. |
| Rich task intent | `Intent`, `Artifact`, `ExpectedBaseSHA` | ruling_required: decide whether Simple Mode tasks remain typed implementation/review/audit work or become title/description only. |
| Dependency recovery | `ReadyAt`, `DependencyOverrides` | ruling_required: dependency gating is retained at claim time, but the plan does not say whether audited override/readiness timestamps survive. |
| Evidence | `Evidence`, `CommandEvidence` | ruling_required: plain `done --evidence` may keep a string, while immutable command evidence likely folds into top-level `verify`; avoid keeping both without an explicit authority rule. |
